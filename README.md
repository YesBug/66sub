# 66sub

**AI 订阅充值与数字商品自动交付系统**

66sub 面向经营 AI 会员充值、激活码和数字商品的商家，将商品展示、在线收款、充值交付、库存管理和售后服务放在同一套系统中。商家可以使用自己的域名与品牌独立部署，按业务需要配置商品、支付方式和交付渠道。

它既支持向用户自己的账号充值订阅，也支持付款后自动发放预先准备的商品内容，不必为两类业务分别搭建网站。

## 适合哪些业务

- **AI 订阅充值商家**：销售不同产品的会员套餐，按商品要求收集充值资料并跟踪处理结果。
- **数字商品商家**：导入激活码、账号交付资料或其他文本商品，付款后自动交付给用户。
- **已有渠道的运营团队**：将自己的上游渠道、库存和支付账号接入统一商城。
- **希望经营独立品牌的团队**：使用自己的域名、LOGO、产品分类、菜单和客服入口。

## 商品与交付

| 业务方式 | 用户体验 | 商家管理 |
| --- | --- | --- |
| 订阅充值 | 选择套餐、付款、提交所需资料、查看充值进度 | 配置渠道与资料类型，管理充值凭证和异常订单 |
| 数字商品自动发货 | 付款后进入订单页面领取商品内容 | 按商品导入库存，查看交付记录与库存状态 |
| 销售兑换码 | 输入销售兑换码，按提示完成兑换 | 生成和管理兑换码，关联商品及兑换记录 |

订阅充值已有 ChatGPT、Claude、Perplexity、Suno、Grok 等产品的渠道接入。具体套餐、账号条件和资料要求以所选渠道及交付版本为准。

商家也可以添加自定义产品分类和自动发货商品。新增商品名称不等于接入一个新的充值服务；新上游接口需要单独适配。

### 让用户清楚知道下一步

- 产品分类、规格、价格和库存状态集中展示，缺货套餐不可购买。
- 提供常规结账与快捷购买入口，适配不同的购买习惯。
- 按商品展示充值说明、注意事项和资料获取教程。
- 订单页面展示付款、充值或发货状态，用户可以继续处理未完成步骤。
- 支持订单查询、消息通知和工单售后，减少反复询问订单进度。

## 品牌与前台

**用自己的品牌经营，而不是沿用一套固定商城名称。**

- 自定义站点名称、LOGO、网站图标、页脚信息和客服联系入口。
- 管理产品分类、分类图标、套餐名称、商品介绍和上架顺序。
- 编辑顶部菜单名称、链接、排序及显示位置。
- 提供经典蓝白与简约商城两套前台模板。
- 覆盖首页、产品页、下单、订单处理及用户中心，支持桌面和手机访问。
- 提供中英文界面切换；商家自定义文案需维护对应内容。
- 支持配置 SEO 信息与商品落地页。

## 收款与结账

按目标客户与商户资质选择支付方式，前台展示顺序可以单独调整。

| 接入方式 | 支持的使用场景 |
| --- | --- |
| 聚合支付接口 | 对接兼容协议的支付宝、微信支付渠道 |
| Stripe | 托管收银台及商户账号已开通的支付方式 |
| Payssion | 国际本地支付，按商户账号实际开通的方式使用 |
| Epusdt | 数字货币收款，币种与网络以接入网关提供的选项为准 |
| 账户余额 | 登录用户通过站内余额购买商品 |

结账功能包括优惠码、电子发票申请、适用渠道的手续费配置，以及需要换汇时的统一汇率配置。订单确认页展示实际应付金额。

**支付接口接入不包含支付账号、商户资质或收款额度。** 商家需要自行开通并配置相关服务；可用支付方式、地区、币种和费用受支付服务商规则约束。

## 运营功能

### 商品与库存

管理套餐售价、经营成本、展示排序、交付类型和充值渠道。充值凭证与自动发货库存分别管理，支持导入、筛选及适用的批量操作；充值凭证核验能力以渠道接口为准。

库存状态与订单关联展示，便于查看可用、占用、已使用和异常凭证，并配置库存预警。

### 订单与售后

- 在商品订单中查看支付信息、交付状态与关联处理记录。
- 按状态、商品和日期等条件筛选订单，支持导出。
- 对异常订单进行核查、锁定、备注或人工处理。
- 管理退款状态与记录；原路退款能力取决于渠道，其他情形按支持的方式处理。
- 通过工单跟进支付、充值、账号及退款售后问题。

### 经营概览

按经营日期查看商城成交、实收、商品收入、成本与净收益估算，结合商品库存了解经营情况。成本配置保留订单快照，退款与附加费用按系统统计口径处理。

经营统计用于运营分析，不替代会计、税务或支付服务商的结算账单。

### 推广与转化

- 优惠券、活动公告和推广邀请链接。
- 返佣规则、佣金记录及结算管理。
- Google Ads 购买转化追踪，并提供开始结账、商品浏览等可选事件配置。
- 商品落地页与快捷购买流程，方便对接不同推广入口。

广告追踪仍受用户同意设置、浏览器限制、广告拦截和平台归因规则影响，不承诺转化百分之百上报，也不承诺投放收益。

## 用户中心

用户可以在自己的账户中查看订单、余额明细、订阅记录、到期提醒、推广收益和售后工单，并管理个人资料与登录安全。

通知支持邮箱、WxPusher、企业微信机器人和飞书机器人，可按已开放的渠道及事件配置。通知送达依赖相关服务配置与可用性。

## API 与交易保护

系统提供开放兑换 API 与接口文档，支持根据兑换码识别对应商品和所需资料，方便对接已有业务系统。

交易处理包含以下保护机制：

- 在服务端计算和核对金额，不以浏览器传入的价格作为付款依据。
- 按支付渠道协议校验回调，并检查订单、金额、币种和支付状态。
- 使用数据库事务、行锁及幂等处理控制重复入账和重复提交。
- 在交付操作中检查订单付款、退款和锁定状态。
- 对支付密钥等敏感配置加密保存，并为管理操作提供审计记录。
- 对关键接口实施身份校验和频率限制。

这些机制用于降低交易风险，不代表软件不存在漏洞。生产运营仍需要 HTTPS、访问控制、数据备份、安全更新和必要的合规评估。

## 部署与交付

66sub 支持独立服务器部署，应用使用 Next.js、React、TypeScript 与 MySQL，推荐通过 Docker Compose 管理运行环境。

商家需要准备：

1. 服务器、域名及 HTTPS。
2. MySQL 数据库与定期备份方案。
3. 自有支付账号、充值渠道及商品库存。
4. 邮件或其他需要启用的通知服务。

程序支持启动时执行数据库迁移。生产升级前应备份数据库与配置，并保留可恢复的版本；加密密钥需妥善保存。

具体交付版本、安装方式、授权范围、更新服务、技术支持与定制内容，在购买前确认。服务器、域名、支付费用及第三方渠道费用不包含在软件能力说明中。

## 常见问题

### 买到的是系统还是充值货源

66sub 是商城与交付管理软件，不附带会员订阅、充值额度、支付账号或上游库存。商家需要自行准备并合规使用相关服务。

### 可以使用自己的品牌吗

可以配置自己的站点名称、域名、LOGO、商品分类和客服信息。具体品牌展示及去标识范围以交付约定为准。

### 可以同时销售订阅充值和自动发货商品吗

可以。不同商品使用各自的交付类型、说明和库存，用户在订单内按商品要求完成充值或领取内容。

### 支持其他产品和渠道吗

支持管理自定义产品和自动发货商品。新充值渠道、新支付协议或特殊业务流程需要评估接口后适配，不能仅填写名称就自动接通。

### 提供源码或者永久授权吗

源码交付、站点数量、授权期限与更新服务需要单独确认，本仓库公开不代表系统开源或免费商用。商业授权中心及自动激活功能仍在规划中，不作为当前已交付功能宣传。

### 是否保证充值成功或经营收益

不保证。充值结果取决于账号条件、所选商品、库存和上游服务；经营结果取决于商家的产品、定价、渠道及运营。系统提供流程管理与状态记录，不替代第三方服务本身。
